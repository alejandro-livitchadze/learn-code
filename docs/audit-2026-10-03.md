# Audit 2026-10-03

Branch `develop` at `ffd1ce7`, read-only. Nothing in the repository was changed; the checks only wrote ignored build output.

## Verdict

The foundation is sound, but `develop` is not ready for agent-written lessons. `pnpm lesson check` passes lessons that cannot be played or solved, and it is the only gate the upcoming lesson tasks (L1 to L3, M3 to M5) have. The SQL lab has two learner-facing bugs: a session that Reset cannot recover, and date/time values shown wrongly. Result comparison exists in three copies that already disagree. The Playwright suite that carries most acceptance criteria for P6 to P8b is not in CI and fails on macOS. Fix F1 to F5 before starting V1 or any lesson task; the rest can be scheduled.

The architecture itself held up: packages are layered correctly, the widget registry is exhaustive, nothing renders lesson text as HTML, and PGlite is a lazy chunk. The D5 headline numbers reproduce from the extraction files (209 vacancies, 158 JS, 77 postgresql, 31 nestjs).

## Findings

### 1. [blocker] `lesson check` passes lessons that cannot be played or solved

A probe lesson with all of the following returned zero lint or compile issues:

- **Duplicate step ids.** Results are keyed by step id (`apps/web/src/player/reducer.ts:41`), so answering one step completes its twin. `packages/lesson-schema/src/lesson.ts:11` has no uniqueness check.
- **`fillBlanks` blank missing from the template.** `checkFillBlanks` returned `correct: false` with every visible input right, so the step is unsolvable. A `___ghost___` marker with no blank entry renders an input that is never checked (`packages/widgets/src/check.ts:67-81`).
- **Unknown concept ids** in the lesson and in steps. `registries.concepts` is loaded but no rule reads it (`packages/lesson-compiler/src/lint/rules.ts`).
- **Unknown misconception id on a blank.** Rule 5 covers only predict, recall and firesideChat (`rules.ts:118-128`).
- **Step kinds with no widget.** 13 of 21 kinds map to `Unimplemented` (`packages/widgets/src/registry.tsx:10-32`).
- **Frontmatter `id`/`courseId` different from the folder.** The player fetches seeds from `/seeds/<courseId>/<id>` (`LessonPlayer.tsx:162`) while the route serves by folder name (`apps/web/src/lib/seeds.ts:34-43`), so the lab gets a 404.
- **8 steps.** The schema says `min(8)`; `00-context.md` section 2 says 12 to 20.
- **No reference check for `fillBlanks`.** E01 says the reference solution must pass, and E03 task 3 says the linter reuses the checking functions.

### 2. [major] A learner can put the SQL session into a state that "Reset database" cannot recover

`SqlRunner.reset()` only runs `drop schema if exists public cascade; create schema public;` and then the seed (`packages/sql-engine/src/runner.ts:18,32-35`). Probe against the inline engine, which shares `SqlRunner` with the worker:

- After `begin; select 1/0;` every query returns `25P02 current transaction is aborted`, and `reset()` throws the same error.
- After `set search_path to nowhere`, `reset()` drops `public`, then throws `no schema has been selected to create in`. The seed tables are gone (`42P01 relation "t" does not exist`).
- A learner-created schema (`keep.x`) survives reset.

In the widget, a failed reset moves to the `failed` phase (`SqlLab.tsx:222-226`) and only a page reload helps. Module 1 teaches transactions, so `begin` will be typed constantly. `engine.test.ts:144` covers only the happy path.

```

- Status: todo

- Paths: `packages/sql-engine/**`
```

### 5. [major] Date and time values are shown wrongly and depend on the machine's time zone

`normalizeValue` turns a JavaScript `Date` into `toISOString()` (`packages/sql-engine/src/normalize.ts:9,24`; same in `verify/format.ts:4`). Probe on this machine (UTC+2):

- `date '2024-03-10'` displays as `2024-03-10T00:00:00.000Z`.
- `timestamp '2024-03-10 12:00:00'` displays as `2024-03-10T10:00:00.000Z`, shifted two hours.
- A predict step declaring `2024-03-10 | 1.50` fails with `the sample printed "2024-03-10T00:00:00.000Z | 1.50"`.

A lesson would have to declare output PostgreSQL never prints, and timestamp outputs would differ between the author's laptop and CI.

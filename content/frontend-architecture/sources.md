# Sources: current state of Module Federation and neighbours

Course: `frontend-architecture` (E09). This file is the record that E09 correctness rule 2 asks for. Lessons and the example project (M1) take versions, package names and "what is deprecated" from here, not from memory.

## How to read this file

- Every entry has a **Checked** date. That is the day the linked page was opened and read. All entries below were checked on **2026-10-06**.
- Only primary sources are used (E09 rule 1): module-federation.io, webpack.js.org, rspack.rs, rsbuild.rs, vite.dev, rolldown.rs, the official plugin repositories on github.com, single-spa.js.org, developer.mozilla.org, react.dev, and the npm registry for exact published versions.
- An entry records what the page says. Where a conclusion is ours, it is marked **Inference**. Where a primary source could not confirm something, it is marked **Unconfirmed**. Do not teach an unconfirmed item as fact.
- Versions move fast (`@module-federation/enhanced` had 22 stable releases between 2026-02-06 and 2026-09-26). Re-check section 2 before M1 pins versions, and again before each lesson is written.
- `rspack.dev` and `rsbuild.dev` (named in E09) answer with a 301 redirect to `rspack.rs` and `rsbuild.rs`. Links below use the new hosts. Checked: 2026-10-06.

Further statements, each checked 2026-10-06:

- The stable-release post lists the ecosystem as Bundler: Webpack, Rspack, Rollup, Rolldown; Build tool: Rsbuild, Vite, Metro; Framework/tool: Modern.js, Next.js, Rspress, Rslib, Storybook; UI library: React, Vue, React Native. [MF 2.0 Stable Release](https://module-federation.io/blog/v2-stable-version.html)
- SSR: the same post says you can use MF SSR "directly within Modern.js". The Modern.js page says the integration "includes Server-Side Rendering (SSR)". [Modern.js](https://module-federation.io/integrations/framework/modernjs/index.html)
- Rspack: "The Rspack team works closely with the Module Federation development team and provides first-class support for Module Federation." [Rspack: Module Federation](https://rspack.rs/guide/advanced/module-federation)
- Rsbuild has two ways in: the v2.0 plugin `@module-federation/rsbuild-plugin`, or the built-in v1.5 through the `moduleFederation.options` config key. Limitation stated on the page: "The Module Federation runtime does not yet support ESM output. Avoid setting `output.module: true`". [Rsbuild: Module Federation](https://rsbuild.rs/guide/advanced/module-federation)
- Webpack still ships its own plugin, `webpack.container.ModuleFederationPlugin`. The webpack pages describe it without a deprecation notice and do not mention `@module-federation/enhanced`. [Concept](https://webpack.js.org/concepts/module-federation/), [plugin reference](https://webpack.js.org/plugins/module-federation-plugin/)
- Vite: the plugin page says that all configuration options are supported except `dev`, and lists "hot update when consuming remote modules" and "nuxt ssr" as roadmap items, so they are not available yet. [Vite](https://module-federation.io/integrations/build-tool/vite.html)
- Vite: with `@module-federation/vite` the string shorthand for a remote is a `var` remote; a Vite ESM remote must be declared with `type: 'module'`. The plugin can consume Vite module remotes and `var` remotes built by Vite, Webpack and Rspack. [Migrating from OriginJS](https://github.com/module-federation/vite/blob/main/docs/MIGRATING_FROM_ORIGINJS.md)
- Pure runtime: remotes can be loaded with the runtime API and no build plugin, with limits the page lists (no `import` syntax for remotes, no remote type hints, `shared` must be given concrete versions). A project that exposes modules must use a build plugin. [Runtime Access](https://module-federation.io/guide/runtime/index.html), [Integrations](https://module-federation.io/integrations/index.html)

**Unconfirmed** (checked 2026-10-06, no primary source found):

- Rollup and Rolldown appear in the stable-release post's list, but module-federation.io has no integration page for either, and the Rolldown documentation (`https://rolldown.rs/llms-full.txt`) does not contain the word "federation". Which package provides that support, and how complete it is, is unconfirmed.
- The `@module-federation/vite` README says "Vite and VoidZero recommend this plugin" and links to a LinkedIn post. The Vite documentation (`https://vite.dev/llms-full.txt`) mentions module federation only in a paragraph about a deployment platform and names no plugin. Treat the recommendation as the plugin authors' claim, not as a statement by Vite.
- Angular: the overview page names no package. The sub-pages (Angular CLI, Nx) were not read for this file.
- Next.js 16: not in the plugin's peer range and not listed under "Supports" (`next ^15 || ^14 || ^13 || ^12`). Whether it works is unconfirmed.

**Inference, for M1 (labelled opinion, not a quote):** the documentation never says "the recommended bundler is X". The evidence for a default is indirect: the Quick Start scaffolds only Rsbuild, Rslib and Modern.js projects and its worked example is Rsbuild; the Rspack and Rsbuild sites claim first-class support. A React host with two remotes on Rsbuild with `@module-federation/rsbuild-plugin` and `mf-manifest.json` remotes is therefore the setup closest to what the official documentation shows today. M1 makes the final choice and must re-check the versions in section 2.

Not deprecated, but easy to mistake for the current default:

- **Webpack's built-in `ModuleFederationPlugin`** (`webpack.container`). webpack.js.org documents it with no deprecation notice. It is Module Federation v1.0 in Rspack's terms: no manifest, no runtime plugins, no type hints. A lesson may show it to explain where the idea came from, but the default setup in this course is a v2.0 plugin. Sources: [webpack plugin reference](https://webpack.js.org/plugins/module-federation-plugin/), [Rspack: Module Federation](https://rspack.rs/guide/advanced/module-federation). Checked: 2026-10-06.
- **`@originjs/vite-plugin-federation`**. Not marked deprecated on npm and the GitHub repository is not archived. The registry shows `latest` 1.4.1, published 2025-04-12; the repository's last push is 2025-05-17 (GitHub API, checked 2026-10-06). It is a separate implementation, not the Module Federation runtime: the official Vite plugin ships a migration guide away from it. Whether it is still maintained is **unconfirmed**; this course uses `@module-federation/vite` if it shows Vite at all. Sources: [OriginJS README](https://github.com/originjs/vite-plugin-federation/blob/main/README.md), [Migrating from OriginJS](https://github.com/module-federation/vite/blob/main/docs/MIGRATING_FROM_ORIGINJS.md).
- **`@module-federation/enhanced@0.x`**. Not deprecated on npm, but superseded by `2.x` since 2026-02-06 (section 1).
- **Asynchronous entry file (`import('./bootstrap')`)**. The stable-release post says async startup was rewritten in Rust and "you no longer need to configure asynchronous entry points to get equivalent capabilities". The documentation also describes `experiments.asyncStartup` as an "experimental feature". Which bundlers apply it by default is **unconfirmed**; M1 must record what the example project actually needs. Source: [MF 2.0 Stable Release](https://module-federation.io/blog/v2-stable-version.html), [Async Startup](https://module-federation.io/blog/hoisted-runtime.html). Checked: 2026-10-06.

## 6. Shared dependencies and React (for lesson 4)

| Fact                                                                                                                                                                                                                                        | Source                                                                                    | Checked    |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ---------- |
| `singleton`: "If singleton mode is enabled, the shared dependencies between the producer components and the consumer will only be loaded once, and a higher version will be loaded if the versions are inconsistent."                       | [shared](https://module-federation.io/configure/shared.html)                              | 2026-10-06 |
| `requiredVersion`: the runtime checks that the shared version satisfies it; if it is lower, a warning is given. The exact behavior on a mismatch must be recorded from the M1 example, not copied from this row (E09 rule 3).               | [shared](https://module-federation.io/configure/shared.html)                              | 2026-10-06 |
